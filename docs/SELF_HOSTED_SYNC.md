# Совместный просмотр с локальными копиями

Каждый участник открывает свою копию фильма в Watch Together. Приложение ведущего
запускает сервер синхронизации на TCP 8999. По сети идут только данные комнаты,
позиция, запуск, пауза, перемотка, скорость и измерения задержки. Видео не передаётся.
Громкость, аудиодорожки и субтитры выбираются независимо на каждом компьютере.

## Как подключиться

1. На обоих компьютерах открыть одинаковую версию фильма. Разница длительности
   более 1,5 секунды блокирует вход с объяснением.
2. Ведущий нажимает Watch Together → Create Room. Сервер работает в процессе
   приложения, пока комната открыта; закрытие комнаты освобождает порт.
3. В поле адреса ведущий указывает доступный гостю адрес, например
   `192.168.1.25:8999` в общей сети или публичный IP с портом через интернет.
4. Скопировать полную ссылку либо Connection Code. Оба содержат адрес, ID комнаты
   и токен доступа. Гость вставляет приглашение в Join Room и нажимает Join.
5. Успешный вход появляется только после ответа сервера. Если ведущий закрывает
   комнату или соединение пропадает, воспроизведение у гостя приостанавливается.

Шестизначный ID комнаты сам по себе не определяет адрес компьютера в интернете.
При ручном вводе ID нужны также адрес ведущего и токен из приглашения. Длинный
Connection Code включает все эти данные и не требует центрального каталога комнат.

## Доступ через интернет

Серверу на домашнем компьютере нужен доступный маршрут от гостя:

- публичный IPv4 ведущего, перенаправление TCP 8999 на его компьютер и разрешение
  входящих соединений Watch Together в фаерволе;
- либо общая VPN-сеть с доступом между компьютерами. В приглашении используется
  VPN-адрес ведущего.

За CGNAT без перенаправления порта или общей VPN один только запуск приложения
не обеспечивает входящие соединения. Автоматический обход NAT и центральный relay
в эту реализацию не входят. Прямой `ws://` не шифрует команды; для доступа через
зашифрованный туннель можно использовать VPN или TLS reverse proxy (`wss://…/ws`).

Архитектурный ориентир: [Syncplay](https://github.com/Syncplay/syncplay) и его
[руководство запуска собственного сервера](https://syncplay.pl/guide/server/).
Это самостоятельный протокол Watch Together, совместимость с серверами Syncplay
не заявляется.

## Проверка

`cargo test -p network --test local_sync_test` проверяет настоящий WebSocket между
двумя плеерами: разные локальные пути, управление в обе стороны, паузу, перемотку,
режим Host Only, недоступный адрес и освобождение порта. Эти тесты выполняются в
CI на macOS и Windows. Проверка реальной пары устройств в разных сетях остаётся
отдельной проверкой доступности адреса и пользовательского интерфейса.

В Windows используется непрозрачное окно и canvas с Software Render API libmpv.
Это устраняет зависимость вывода видео от композиции прозрачных Win32/WebView2
окон. Для ограничения нагрузки кадры имеют размер до 1280×720 и опрашиваются
не чаще примерно 30 раз в секунду. Декодер, аудио и субтитры остаются в libmpv.
CI проверяет не только загрузку DLL, но и получение непрозрачных цветных пикселей.
