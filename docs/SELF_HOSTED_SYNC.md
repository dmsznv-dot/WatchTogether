# Совместный просмотр с локальными копиями

Каждый участник открывает свою копию фильма в Watch Together. Комната живёт в
приложении ведущего. По сети идут только данные комнаты: позиция, запуск, пауза,
перемотка, скорость и измерения задержки. Видео не передаётся. Громкость,
аудиодорожки и субтитры выбираются независимо на каждом компьютере.

## Как подключиться

1. На обоих компьютерах открыть одинаковую версию фильма. Разница длительности
   более 1,5 секунды блокирует вход с объяснением.
2. Ведущий нажимает Watch Together → Create Room и копирует Connection Code
   (`WT2-…`) или ссылку `watchtogether://…`. Адрес вводить не нужно: код уже
   содержит ID комнаты, токен доступа и iroh-адрес компьютера ведущего.
3. Гость вставляет код в Join Room и нажимает Join.
4. Успешный вход появляется только после ответа ведущего. Если ведущий закрывает
   комнату или соединение пропадает, воспроизведение у гостя приостанавливается.

Шестизначный ID комнаты сам по себе не находит компьютер ведущего: нужен полный
код или ссылка. Приглашения `WT1-…` из прошлых версий (с IP и портом 8999) больше
не подходят — приложение попросит ведущего прислать новое.

## Доступ через интернет

Соединение устанавливается через [iroh](https://docs.rs/iroh): QUIC с шифрованием,
пробивкой NAT (а также UPnP/PCP/NAT-PMP) и запасным путём через relay по HTTPS
(TCP 443). Настраивать роутер, пробрасывать порты или поднимать общую VPN не нужно,
CGNAT тоже не мешает. Если прямой путь не находится, команды идут через relay:
сервер видит только зашифрованный трафик, состояние комнаты по-прежнему хранится у
ведущего.

По умолчанию используются публичные relay n0. Свои relay (`iroh-relay`) задаются
переменной окружения `WT_RELAY_URL` — один или несколько URL через запятую.

Проверить связь между двумя компьютерами без приложения можно утилитой
[`wt-nettest`](../tools/nettest/README.md).

Архитектурный ориентир: [Syncplay](https://github.com/Syncplay/syncplay) и его
[руководство запуска собственного сервера](https://syncplay.pl/guide/server/).
Это самостоятельный протокол Watch Together, совместимость с серверами Syncplay
не заявляется.

## Проверка

`cargo test -p network --test local_sync_test` проверяет настоящее iroh-соединение
между двумя плеерами без интернета (relay отключён): разные локальные пути,
управление в обе стороны, паузу, перемотку, режим Host Only, недоступного ведущего и
закрытие соединений. Эти тесты выполняются в CI на macOS и Windows. Путь через
публичные relay проверяет `cargo test -p network --test local_sync_test -- --ignored`
(нужен интернет).

В Windows используется непрозрачное окно и canvas с Software Render API libmpv.
Это устраняет зависимость вывода видео от композиции прозрачных Win32/WebView2
окон. libmpv рисует каждый новый кадр (до 1920×1080) прямо в общую память WebView2
(`PostSharedBufferToScript`), страница загружает его в WebGL-текстуру в темпе экрана —
по IPC идёт только короткий запрос, поэтому 1080p60 не упирается в копирование ~500 МБ/с.
Если WebView2 не поддерживает общие буферы, кадры копируются через IPC, как раньше.
Кадры рисует видеокарта (OpenGL 3+, mpv рендерит во внеэкранный буфер). Если для
монитора с окном в Windows включён HDR, кадры идут линейным светом в 16-битном формате
на HDR-канву WebGPU (`rgba16float`, `toneMapping: extended`), пик яркости берётся из
DXGI; иначе — 8 бит, и mpv сжимает HDR-фильм в обычный диапазон. Режим меняется сам при
переносе окна на другой монитор или переключении HDR. Без OpenGL 3 (например, виртуальные
машины без видеокарты) используется программный рендер libmpv: только SDR, без тон-маппинга.
Декодер, аудио и субтитры остаются в libmpv.
CI проверяет не только загрузку DLL, но и получение непрозрачных цветных пикселей.
